- **The owner's design for the `_after_turn` tools: between turns, or when idle** (read from Claude Code 2.1.319). A plugin's `$.command.run` is queued at the lowest priority (`later`), behind a background task's notification (`next`) and anything queued before it; only commands queued during a session's start, and in a headless run input a turn event queued, go first. So a command can't run between turns ahead of what is waiting, in an interactive session. Compacting can: `$.session.compact` from the turn's end itself takes the session at once.
  - **self-compact 0.3.0**: `compact_after_turn` takes `when`: `between-turns` (the default) compacts from the turn's end itself, ahead of anything queued meanwhile, which then runs on the compacted conversation; `idle` waits half a second, as before, so anything queued goes first. A turn that got there first puts either off to that turn's end, as before.
  - **Every other `_after_turn` tool** (exit, clear, restart, switch, reload, MCP reconnect, Remote Control's connect and rename) says in its description that it runs only when the session is idle, why, and that under a nonstop stream of work and notifications it may run in the distant future; exit, clear, restart and switch add that a turn that starts first cancels them, so nothing waiting is lost or carried into another conversation. No choice is offered where the engine can't make one.
- **self-switch: a left record written by two writers** (agent-coordinator-3000#81). An in-place go has the coordinator and self-switch each write the left record of the conversation just left. The second now finds the first's record of the same move (the same conversation, how and process, written within 30 s, over the same transcript size and time, naming the go this write names, if any) and counts it as written, before its write and again when its move fails on a file that appeared meanwhile; any other record is replaced, as before. A left record that really isn't written says so in one plain sentence ("self-switch couldn't record that this session left conversation <id>, so for about 10 minutes a switch back to it is refused as if it were still open."); the script's own words go to the debug log, and no raw PowerShell error record (`#< CLIXML`) reaches the screen, there or in a probe's or a launcher's failure (`plainOutput`).
- **self-switch: a refused switch delivers nothing** (M27d). The leaving row and the ticket are written right before the final command, past the last look, so a switch refused there says nothing moved and leaves no ticket. A ticket is taken only by the process it is for: an in-place move's by the process that wrote it, a move that starts another process's by one started after the ticket. A session resuming the conversation by hand meanwhile leaves it.
- **An unaccounted `claude.exe` no longer holds every switch, when it is Claude Code's own or a test's** (M27 finding 2). The probe sets aside (`aside`, `GET_ASIDE`) Claude Code's /fork daemon (`daemon ...`), the pty host of a background session (`--bg-pty-host`), and a test stub by its folder, `%TEMP%\claude-self-tools-test-stubs` (every stub the tests compile goes there: `stubWork`); liveness counts them accounted. L2 still reads their command lines; the session count and the floor still count them; any other `claude.exe` without a registry entry still reads unknown.
- **The window and the slot runner wait for the old process by its handle** (F1). A process's exit code reads set 55 to 97 ms (measured on real exits) before it is signaled and dropped from the process table, and `Wait-Process` returns at the exit code. `Wait-Gone` waits with `WaitForExit` on the process's handle, and both it and `Test-Gone` check its start time, so a process id the system gave to another process isn't waited for. `TEST_GONE`'s comment now says this; the earlier one (a handle held keeps an exited process in the table) wasn't borne out by the live checks.

The rows and toasts that said a window gives up after 10 minutes say it keeps waiting.

## 2026-11-06: self-check 0.2.0, the Bash env guard

- **self-check 0.2.0**: guards the Bash tool against dying of its own session env on Windows ([anthropics/claude-code#103861](https://github.com/anthropics/claude-code/issues/103861)).
  - **The cause** (read from Claude Code 2.1.319's bundle, and reproduced with Git Bash):
    - Claude Code puts this session's env hook files, `~/.claude/session-env/<session>/(setup|sessionstart|cwdchanged|filechanged)-hook-<n>.sh`, into every Bash call's `bash -c` string, ahead of the command.
    - Git Bash runs only the first 8,186 characters of that string and drops the rest without a word.
    - A SessionStart hook that appends at every start (the Vercel plugin adds three `export` lines at each startup, resume, clear and compact) grows the files for as long as the session id lives. Long commands are cut first (`unexpected EOF`), then every command (exit 0, no output). A resume reads the same files, so it never helped.
  - **The dedupe**, new: in each hook file, only the last assignment of each variable is kept, in order, so the environment is the same.
    - Only setup and sessionstart files are rewritten. Claude Code empties cwdchanged and filechanged files itself mid-session, so those are measured, never rewritten.
    - A file is left as it is when any line isn't a plain assignment (Claude Code's own test), when a line ends in white space a shell keeps (a no-break space, a vertical tab), when a variable any earlier line exported is set without `export` by its last line, when it isn't clean UTF-8, when it wouldn't get shorter, when a backup path is a link or not a plain file, or when it changed between the first read and the one right before the rewrite. That last check narrows the window for another writer; without an atomic rename it can't close it.
    - The file is read back after the rewrite. Exactly what was written, or that followed only by whole plain assignment lines (another writer's append), is kept, the append with it; anything else puts the text first read back. When that fails too, a toast names the file and its `.orig` and `.bak`, and `tools_check` says it may be damaged in place of the fresh-process hint, until it reads as plain assignments again.
    - Nothing is rewritten while the setup and sessionstart files total 2 KB or less. Backups: `<name>.orig`, written once (the file before the guard first touched it), and `<name>.bak` (before the latest dedupe), overwritten. Names, counts and lengths are logged to the debug log, never a value; another plugin's refusal is quoted.
    - A deadline: no write starts after 5 seconds; one already under way, or putting a file back, is waited for 5 seconds more, and on a disk slower still can land after the start has returned.
    - **When:** right after every session start, once the SessionStart hooks beneath the plugin have appended (they are settings hooks, below every hooks module in the classic chain). Claude Code drops its cached copy of the env script after each SessionStart hook and builds it again at the next Bash call, so that call reads the deduped files. Also in a check that finds the env AT RISK or BROKEN, for a session already over the line. That dedupe doesn't drop Claude Code's cached copy, so the check's line then ends with the next step: move the PowerShell tool's directory away and back in two calls, then retry Bash.
    - **New setting** `envDedupe`, on by default; `off` never rewrites the files.
  - **`tools_check` says the env's headroom**, on a line after Bash's: the characters every Bash call carries, the room left for the command, and a verdict, BROKEN (none left), AT RISK (under 2,000) or OK.
  - **When the dedupe refused a file** of an env at risk, a further hint says never to edit it by hand and to tell the person which file it is.
  - **The check at resume is skipped** once another conversation runs in the process (a /clear, a switch).
  - **The repair for a dead Bash is corrected.** When its env is AT RISK, BROKEN or can't be measured, the answer names the env-size cause, the dedupe, and moving the PowerShell tool's directory and back in two calls, so Claude Code reads the files again; it no longer says a fresh process repairs it, since a resume reads the same files. A dead Bash with an OK env, and any other dead tool, still get the fresh-process hint. The toast at resume says which.
  - **Tests**, fakes only (an in-memory env folder under a Temp root, fake variables with low-entropy values, a generated session id; any path outside the root is refused): the refuse-unless-plain rule and Claude Code's regex pinned, the export rule, last-wins order with the same environment after, one backup over forty starts, the 2,048 / 2,049-byte threshold, the verdict boundaries (7,716 / 7,715 / 5,717 / 5,716 characters), a file changed meanwhile, the setting off, subagents, off Windows, `CLAUDE_ENV_FILE` counted and never written, the next step a check's line gives after its own dedupe, and the hints and toast. Also three-line export cases, trailing white space, the byte threshold with non-ASCII text, a timed-out dedupe, a failed and a torn rewrite put back, an append after the rewrite kept, a rewrite and its putting back both failing (toast, damaged line and hint), backup paths and hook-named entries that are links or folders, `CLAUDE_CONFIG_DIR` (used; unsafe turns it off, never a fallback), and the resume check after a switch.
  - **`scripts/env-guard-bash.test.mjs`**, new: runs the env script Claude Code would build, before and after the dedupe, in real Git Bash over a corpus of cases (quotes and escapes, `export` and `declare -x`, unexported then exported, comments holding `=`, CRLF with and without a trailing comment, a BOM, empty and comment-only files, a no-break space or a vertical tab before a trailing comment, two files setting one variable, a refused file between two deduped ones), and compares the variables each run ends with. Fake values, in a new temp folder; skipped off Windows or without Git Bash.

## 2026-11-06: self-remote-control 0.3.0, after a login change: Remote Control reconnected, a cut-off turn resumed, and a shared Remote Control lock

- **self-remote-control 0.3.0**:
  - **After a login change**, each session reconnects its own Remote Control and resumes a turn the change cut off, without anyone typing. It works whether the login changed through `/login` in one session or through a tool that swaps the stored login file, for example when an account hits its usage limit.
    - **What Claude Code does on its own** (read from its 2.1.319 source):
      - it re-reads the login file once its modification time changes;
      - Remote Control stops in a session whose signed-in account changed (*signed-in claude.ai account or organization changed on this machine*), and the remote-control command reads not connected about ten seconds later;
      - a turn the limit cut off stays where it stopped.
    - **Seeing the change.** The plugin API has no event for a login change, so the plugin checks every 5 seconds.

The switch refuses, naming the evidence, when `to` is held by a running Claude Code, named on a command line, written in the last 10 minutes, alive by its heartbeat, or claimed by another move; and when anything can't be read, a registry file is of a shape not verified (a key outside the 18 seen, or `pid`, `sessionId`, `procStart` or `status` missing or of another type), a `claude.exe` is accounted for by no registry, or `to` has no transcript here, or two.
  - **Only at a safe point.** It refuses while a subagent, a background Bash, PowerShell or Monitor job, git (or a git operation in flight in any worktree), a build, test or lint, a dev server, Playwright or a heavy-slot job runs under the session, and for an in-place switch while the checkout has uncommitted changes. Anything unreadable holds it.
  - **The claim lock** (`%LOCALAPPDATA%\claude-self-tools\claims\<id>.lock`) is taken with CreateNew in the probe run that judged, and released where the conversation arrives. A stale lock is taken over, and a lock released, through one handle that keeps every other writer out, never by a delete and a create; a release a reader blocks is tried again, then left in place and logged; an in-place switch reads the claim again right before `/resume`.
  - **Coordinated mode.** While the coordinator's gate file for the conversation says `coordinated: true` (at most a day old), every call refuses. `requireCoordinator: on` refuses where there is no gate file.
  - **The slot runner** (`slot/claude-slot.ps1`) keeps a Windows Terminal pane: it runs `claude`, and when it exits, resumes the conversation a switch or restart left it a record for, in the same pane, after checking it all again, the folder being the conversation's own project among it. The plugins use it only when its SHA-256 is the one they ship; the slot's id is compared as the exact string the probe prints. The pane's profile line uses `-ExecutionPolicy RemoteSigned`, and the runner clears it before `claude` starts.
  - **The last look.** A registry file that can't be read at the last moment is read twice more, 250 ms apart; still unknown, the window or slot says so and gives the `claude --resume <id>` line to run by hand.
  - No transport passes a permission flag: the resumed conversation starts in the mode a new session would.
  - It refuses subagents, outside a terminal, off Windows, within 2 minutes of a switch, and while subagents run. A new turn or an interrupted one cancels it; a new turn's cancel is told in a plugin row, and from the third in a row the row says the session is busy: queue it again when idle, or ask the merger or the owner.
  - Where the coordinator runs switches, it refuses: *ask the merger or the owner for a wrap-up*.
- **self-restart 0.1.3**: its launcher is now the shared one, version 2.
  - It takes the claim lock on the conversation, with CreateNew, and the resumed session releases it, so a switch moving the same conversation can't resume it too.
  - After the wait, right before `claude --resume`, the window reads the registry and the process table again and resumes nothing if another process holds the conversation, or if the claim no longer names it.
  - In a pane set up as a slot, it leaves the slot a record instead of opening a window, when the start folder is one the runner takes.
  - Right before the launch it runs the full safe point, as a switch does: a background job, git, a build, a dev server or a heavy-slot job under the session, git in flight, or anything unreadable holds it.
  - A new turn's cancel is told in a plugin row, counted as for self-switch.
  - The scrub of Claude Code's markers adds `CLAUDE_CODE_SSE_PORT`; no permission flag is passed.
- **The shared machine code**, `shared/hooks/machine.ts`, copied into self-restart and self-switch only: the probe, liveness, the safe point, the transports, the launcher, the claim lock, the gate and the slot runner's hash. It imports nothing but the engine's types, so the coordinator can vendor it byte for byte.

## 2026-11-03: a session clears, exits and restarts itself

Three new plugins. Each queues its action at the call and runs it once the turn ends with an answer. Each cancels it when the turn is interrupted, and refuses subagents, as the others do.

Each also requires the parameter that makes its action safe to take unattended (`handoff` or `reason`), and refuses while a subagent is pending, running or waiting. That is checked at the call and again right before the action. None of them changes a setting, a permission, CLAUDE.md or any other configuration.

- **self-clear 0.1.0**, new:
  - `clear_after_turn` runs `/clear`, then sends `handoff`, which is required, as the cleared conversation's first prompt.
  - A clear starts a conversation under a new session id. If the id hasn't changed, the clear didn't take, and the handoff isn't sent as if it had.
  - A handoff Claude Code drops is kept as a note for the next message.
- **self-exit 0.1.0**, new:
  - `exit_after_turn` runs `/exit`. `reason` is required; an optional `note` is for whoever resumes the session.
  - Before the exit, both are recorded as a conversation row, which a later `claude --resume` loads, and as a transcript line the person sees.
  - It is refused where no one is at the prompt (`-p`, an SDK host).
  - A refused exit, or a session still open a few seconds after `/exit`, is told to the person and the model.
- **self-restart 0.1.0**, new, Windows only:
  - **The launch.** `restart_after_turn` runs Windows PowerShell, by its known path under the Windows folder, on one fixed script whose only variable is the session's id, which must be a UUID. That script opens a new console window with `Start-Process`. Then the session runs `/exit`. Nothing from the tool's input reaches the launch.
  - **The wait.** The window waits for the session's own `claude.exe` to exit, then runs `claude --resume <id>` from PATH in the folder the session started in. After 10 minutes it gives up and says so.
  - **The process walk** takes a parent only while it is older than its child, so a process that reused a gone parent's id is never taken for the session.
  - **A failed resume.** A Claude Code that ends with an error, or within 10 seconds, leaves the window open on the manual `claude --resume <id>` until Enter.
  - **No restart loop.** A second restart of a session within 2 minutes of the last is refused.
  - **The first prompt.** `resume` waits in the plugin's store under the session's id, and the resumed session's copy of the plugin sends it once. One older than 15 minutes is dropped.
- **The update check's list of names** gains the three. The other plugins' copies of the shared file change by that line alone and behave as before, so their versions stand.

## 2026-11-01: the plugins say when they're out of date

Every plugin gets the same update check. Nothing else in them changed.

- When the main session calls one of a plugin's tools, and its last check is 30 minutes old or there hasn't been one, the plugin fetches its own `plugin.json` from the repository's `main` branch: a plain GET of a public file on raw.githubusercontent.com. The plugin adds no headers, query or body, and nothing about the person, the session or the machine; GitHub sees what it sees of any web request (the address, the time, the headers Claude Code sends on its own). It compares the `version` there with the installed one, number by number. The check's time and answer are kept in the plugin's own store, so a reload or another session on the machine uses that answer for the rest of the 30 minutes. Sessions that come due at the same moment each make their one request.
- The tool call never waits on the check. A failure is silence: offline, refused by policy, a 404, a rate limit, no answer within 5 seconds, bad JSON, or a version that isn't three plain numbers.
- When a newer version is out, a toast tells the person, and one of the session's next tool results ends with a fixed line: the plugin's name, the installed and the published versions, and the update steps for the person to run (`claude plugin marketplace update`, `claude plugin update`, then `/reload-plugins` or a new session), closing with "Don't run these yourself unless the person asks." Nothing else from the fetched file reaches the session. A session is told of each check once, and at most once every 30 minutes, kept across reloads, rather than on every call: these tools are called again and again in a long session, and the same line on every call would cost context and get tuned out. The toast follows the same rule.
- New `updateCheck` setting, `on` by default; `off` never checks. Nothing is checked while `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set, to any value, or for a subagent's call.

The versions with it:

- **self-mcp 0.1.1**: the update check, on `reconnect_mcp_after_turn`.

- **self-remote-control 0.2.1**: the update check, on `remote_control`.

## self-remote-control 0.2.0 (2026-10-30)

## self-compact 0.2.2 (2026-10-21)

First public release.

- The `compact_after_turn` tool: the session queues a compaction of its own conversation, with `keep` as the summary instructions. It runs once the current turn ends, one compaction per call, so a session compacts per piece of work.
